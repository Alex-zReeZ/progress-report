## Purpose

This project is a full-stack web application built to manage announcements and user
interactions. The goal was to design and implement a structured application on top of a
headless CMS, with a focus on scalable architecture, secure authentication, and dynamic
frontend/backend communication. It never reached completion, as it was only ever intended as a
prototype.

## Technologies

- Strapi
- React
  - strapi-client
- JWT Authentication
- REST API

## Description

A Strapi backend acts as the headless CMS, handling content, user accounts, and moderation.
A React frontend consumes those services and gives users a clear interface to work with:
end users can create and manage announcements, while administrators moderate content and
manage accounts.

The project was also an opportunity to explore Strapi as an alternative to WordPress, driven by
an unusual authentication requirement. Account creation had to happen through a QR code, with
an access token issued only by scanning it and completing the sign-up on the spot.

## Operational Competencies Acquired

I began by clarifying and documenting the project's requirements and objectives, defining its
general parameters such as scope, responsibilities, and the constraints around authentication
and moderation.

I then researched the available tools and technologies, weighing a headless CMS (Strapi)
against a more traditional WordPress setup and comparing options for a secure, easy-to-set-up
login. Since the login relied on QR-code account creation and token delivery, this also meant
assessing the technical potential and risks of each approach. As a prototype, the application
effectively served as a proof of concept for that custom authentication flow.

I also looked into deployment, since several hosting options were on the table. This involved
identifying the dependencies between the frontend and backend and determining which platform
was best suited to run the application.

Finally, a decision had to be made on content moderation. I compared two implementation
variants, manual moderation before publication versus an automatic process backed by a user
reporting system, then developed the chosen approach conceptually before implementation.
